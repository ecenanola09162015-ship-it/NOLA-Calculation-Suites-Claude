# Project PDF Reports

Both implemented designers offer Simple and Complete PDF exports, with A4 (default) or Letter paper. Column summaries stay on one page. Slab summaries first attempt one page and can use two pages when needed. Text is never silently clipped to enforce a page count: content beyond those limits prompts a shorter description/remarks or Complete Report.

Use Edit Project Information > Project PDF Report Settings for Owner / Client, Building Description, Revision No., Company Name, logos, footer title and report styling. Logos accept PNG/JPEG (5 MB maximum input), are resized while preserving aspect ratio, stored with the owned project, and contained within white header cells. Resetting the Ñola logo restores the supplied brand asset. A missing company logo uses the company name or an empty cell. Changes take effect without reloading the active calculation.

The canonical style is packages/calc-core/src/report-style.json, validated by report-settings.ts and overridable in project settings. It defines fonts/fallbacks, role sizes, margins, spacing and brand colors. DCR colors/thresholds remain in the same shared project design policy used by the interface. Century Gothic is the preferred diagram/interface family; PDF text uses a selectable standard font (Helvetica default, Times Roman or Courier). No licensed Century Gothic font is bundled.

Reports share the report data/section model and PDF renderer under apps/web/src/lib/reports. SVG drawings are generated from the evaluated inputs and rasterized at four times their logical resolution in the browser. Headers and footers are stamped on all pages after pagination, with final Page X of Y values. Complete tables repeat their own headings; long rows can continue rather than losing remarks. Optional quantity sections and schedules are completely omitted when disabled. Exported filenames begin with YYYYMMDD.

The report reflects the existing pilot engine; it does not add new design checks. Column Vux/Vuy are not supplied and column shear, member slenderness and seismic confinement checks are marked not evaluated. Estimating tie spacings are not verified design spacings. Slab deflection is the existing gross-stiffness immediate screen; minimum thickness, punching, long-term/cracked deflection, corner torsion and complete anchorage compliance are not certified. The NSCP 2015 project option continues to use the designer-selected ACI 318-19 calculation basis. Code sections identify the applicable review references; an engineering screen is distinguished from an automated code-compliance check.

Amber results include recorded engineering remarks next to the result. The interface requires nonblank remarks before export. Complete reports retain other explicitly recorded remarks for traceability. Page length depends on load combinations, reinforcement schedule and remarks; representative column/slab fixtures target 4–6 pages, with all combinations retained.
